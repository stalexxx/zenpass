# C04: Extension-to-vault bridge

Goal: Define and implement the approved, zero-knowledge bridge that lets a
browser extension unlock its own ephemeral session and perform encrypted
save/update and TOTP flows without reading the web application's origin-bound
storage or transferring raw keys, passwords, recovery keys, or TOTP secrets
across an untrusted page boundary.

Dependencies: B03, B04, C01, C02.

Status gate: **BLOCKED pending a new ADR and human security approval.** The
chosen architecture must specify the extension authentication/bootstrap flow,
account discovery, key-bundle authorization, origin/message authentication,
session lifetime/lock propagation, encrypted persistence, and exact data that
may cross each boundary. Do not start implementation or change contracts until
that approval is recorded.

Allowed paths after approval: `apps/extension/`, `packages/extension-adapters/`,
`apps/web/`, `packages/sdk/`, and any explicitly approved additive API-contract
or backend paths named by the ADR.

Forbidden paths: `crates/crypto-core/`; existing contract or migration rewrites;
plaintext vault/key/password/TOTP storage, logging, fixtures, analytics, or
cross-origin message payloads.

Inputs: `docs/ux/flows.md`, `docs/security/THREAT-MODEL.md` (T04, T05, T06,
T07, T09, T15, T19), `docs/contracts/api-v1.md`, B03/C01/C02 implementation,
and the approved ADR.

Required implementation after approval: Extension-local OPAQUE/bootstrap flow;
authenticated access to the encrypted key bundle; Worker-owned opaque session;
explicit lock/timeout/restart cleanup; encrypted item retrieval and save/update;
TOTP display/fill through an approved client-side path; and no plaintext
persistence.

Acceptance criteria:

- The extension cannot read the web application's IndexedDB or Worker session.
- A compromised page/content script cannot enumerate vault entries or receive
  credentials before a user-confirmed, exact-origin fill.
- Lock, browser restart, logout, and device revocation make the extension
  session unusable.
- The server continues to receive only opaque key bundles and ciphertext.

Required tests: Chrome and Firefox E2E for independent unlock, lock/restart,
same-origin and hostile-origin autofill, save/update, TOTP, session rotation,
device revoke, and storage/log inspection.

Completion report format: Standard completion report.
