# Q01: System E2E and hardening
Goal: Validate full security and reliability properties across the MVP API, web, and SDK.
Dependencies: B04, B05, C01, C02.
Allowed paths: `tests/e2e/`, `tests/security/`, `docs/security/`, CI test configuration.
Forbidden paths: Product behavior changes without owner task.
Inputs and approved contracts: All frozen contracts and threat model.
Required implementation: Two-device offline/reconnect suite, dump inspection, backup restore drill, fuzz/SAST/dependency/secret/SBOM checks. Full extension hostile-autofill E2E is a C04 follow-on requirement.
Acceptance criteria: Every release gate in MASTER has evidence; findings are classified and assigned.
Required tests: Full E2E and security suite.
Commands to verify: `bun run test:e2e`; `bun audit`; `bun run lint`.
Deliverables: Gate report and finding list.
Risks and escalation conditions: Critical/High finding blocks H02 and R01.
Completion report format: Standard completion report.
