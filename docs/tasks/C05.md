# C05: Migrate web client to React + TypeScript

Goal: Migrate the existing `apps/web` client from the hand-rolled DOM view layer to React with strict TypeScript, without changing the public API, crypto, storage, synchronization, or security behavior.

Dependencies: C01.

Owner: Claude Code Agent.

Allowed paths: `apps/web/`, `bun.lock` (only dependency resolution required for this task).

Forbidden paths: `apps/backend/`, `packages/crypto-wasm/`, `packages/crypto-worker/`, `packages/sdk/`, `packages/domain/`, `packages/importers/`, API contracts, cryptographic code, and security policy documents.

Required implementation:

- Replace the hand-rolled view mounting/rendering layer with React components and typed props/state.
- Convert web source files touched by the migration to TypeScript with strict compiler checks; do not leave an untyped compatibility layer as the primary UI path.
- Preserve onboarding, recovery-kit confirmation, unlock/lock lifecycle, CRUD, search, TOTP, import/export, offline behavior, conflict handling, device management, accessibility announcements, and fail-closed security boundaries from C01.
- Keep crypto operations in the existing Worker/WASM boundary; React components must not receive or persist raw key material outside the existing session abstractions.
- Keep the current Bun build/dev entrypoints unless a replacement is necessary and documented; production output remains `apps/web/dist`.

Acceptance criteria:

- `apps/web` builds with strict TypeScript checking and no `any`-based escape hatch for migrated code.
- Existing web behavior and security invariants remain covered; no vault plaintext, keys, passwords, or TOTP secrets are written to localStorage, URLs, logs, analytics, or test fixtures.
- Existing tests remain green, with component/accessibility coverage added for the React view layer.
- No API, crypto, storage, or sync contract changes.

Required verification:

- `bun run --filter @zkpm/web test`
- `bun run --filter @zkpm/web build`
- `bun run check:boundaries`
- `bun run lint`

Known risks: dependency/bundle-size growth and accidental leakage through component props or error boundaries. Escalate any need to change crypto/session contracts or expose raw key material.

Completion report format: Standard completion report from `docs/plan/INTEGRATOR.md`.
