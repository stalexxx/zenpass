# C01: Web vault
Goal: Implement the web vault MVP over SDK and WASM Worker.
Dependencies: B03, B05, C02, A03.
Allowed paths: `apps/web/`, plus `packages/crypto-wasm/` and `packages/crypto-worker/` (ADR-0008: account-setup/recovery-kit WASM exports only, mechanical wraps of existing `crypto_core` functions, additive to B03/C02's existing exports).
Forbidden paths: Crypto primitives (beyond the narrow ADR-0008 additions above), `crates/crypto-core`, API contract, backend. TOTP code generation must use only the browser's native `crypto.subtle` HMAC (ADR-0008 §3) — no hand-rolled HMAC/hash. No "final" recovery-code display encoding (G-10 remains an open human decision; ADR-0008 §2 sets the provisional-labeling requirement).
Inputs and approved contracts: UX flows, API/sync/crypto contracts.
Required implementation: Onboarding, recovery verification, unlock/lock, CRUD, in-memory search, generator, TOTP, encrypted IndexedDB, import/export.
Acceptance criteria: No keys/vault plaintext in localStorage, analytics, URLs, logs, or crash reports.
Required tests: Component, accessibility, lock lifecycle, import/export, offline, and browser smoke tests.
Commands to verify: `bun run --filter @zkpm/web test`; `bun run --filter @zkpm/web build`.
Deliverables: Web app and UI test report.
Risks and escalation conditions: Escalate any browser API that exposes raw key material.
Completion report format: Standard completion report.
