# C03: Browser extensions
Goal: Deliver the reviewed Chrome/Firefox extension security baseline: separate
manifests, minimum permissions, background-only volatile session abstraction,
popup/content-script boundary, and fail-closed origin/form policy. Full
extension unlock, encrypted save/update, and TOTP are deferred to C04 by the
2026-09-04 MVP scope decision.
Dependencies: C01, C02.
Allowed paths: `apps/extension/`, `packages/extension-adapters/`.
Forbidden paths: Backend, crypto primitives, contract edits.
Inputs and approved contracts: UX flows, SDK, origin-matching rules, WebExtensions platform constraints.
Required implementation: Background service worker session, popup, content-script minimal data flow, separate manifests, minimal permissions, no remote code.
Acceptance criteria: Never autofill HTTP, look-alike, ambiguous, or untrusted cross-origin forms.
Required tests: Unit/build/manifest permission tests for HTTPS, look-alike,
iframe, subdomain, hidden-field, cross-origin-form, confirmation, and lock
refusal flows. Full Chromium/Firefox E2E moves to C04.
Commands to verify: `bun run --filter @zkpm/extension test`; `bun run --filter @zkpm/extension build`.
Deliverables: Buildable Chrome/Firefox packages and permission review. Store
submission is a C04 deliverable.
Risks and escalation conditions: Escalate browser incompatibility rather than weakening origin checks.
Completion report format: Standard completion report.
