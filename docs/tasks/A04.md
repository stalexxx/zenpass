# A04: Crypto specification
Goal: Define byte-level `crypto-envelope/v1`, key hierarchy, domain separation, nonce rules, Argon2id calibration, OPAQUE suite, recovery reset, and vectors.
Dependencies: A01, A02.
Allowed paths: `docs/contracts/crypto-envelope-v1.md`, `fixtures/crypto/`, `packages/crypto-fixtures/`, `docs/decisions/ADR-*.md`.
Forbidden paths: Production crypto code, backend, client UI, root workspace manifests, lockfiles.
Inputs and approved contracts: RFC 9807 OPAQUE; RFC 9106 Argon2id; `docs/security/THREAT-MODEL.md`.
Required implementation: Canonical CBOR schema, typed errors, versioning, test vectors, malformed examples, and migration rules. For the rework recorded in H01, create the dependency-free Bun fixture harness in `packages/crypto-fixtures/`; it must consume test-only vectors and a separately supplied validator adapter, never implement cryptographic operations itself.
Acceptance criteria: A Rust and WASM implementer can implement without design decisions.
Required tests: Independent vector verification and canonicalization tests.
Commands to verify: `bun run --filter crypto-fixtures test`.
Rework scope: The A04 rework owns G-01..G-04, G-09, and G-11. It may correct/add public test fixtures and harness checks, but must not alter the normative meaning of a fixture schema, select a production library, add a dependency, or modify `crypto-envelope/v1`; each requires a separately approved decision. Use Bun only; do not use pnpm. G-05 evidence conclusion, G-06 selection, G-07 calibration evidence disposition, and G-10 recovery-code display decision remain human H01 reviewer work.
Deliverables: Frozen crypto contract pending H01.
Risks and escalation conditions: Any algorithm or suite change requires human security approval.
Completion report format: Standard completion report.
